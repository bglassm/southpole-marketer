## 자격증명 검사 결과와 한계

검사한 일반 파일과 커밋 메타데이터에서 실제 토큰·개인키로 판단할 수 있는 값을 발견하지 못했다. 두 역사적 `.env.example` 버전의 자격증명 항목은 공란 또는 명시적 교체용 예제였다. legacy collector/aggregator의 credential 항목은 ID·이름 참조이며 OAuth 비밀값을 내보낸 형태는 아니었다. legacy export 5개에서 저장된 실행 데이터에 해당하는 비어 있지 않은 `pinData`, `staticData`, `executionData`, `binary`도 확인되지 않았다.

컨테이너 내부의 n8n 홈 경로 4곳은 개인 경로 오탐으로 분류했다. node ID, UUID, 빌드 태그, 환경 변수 이름과 `KEYWORD`가 포함된 탭 이름도 자격증명으로 취급하지 않았다.

이 결과는 사용자 정의 패턴과 수동 검토의 범위다. 알 수 없는 토큰 형식, 암호화·인코딩된 값, 외부 파일이나 서비스의 안전성을 보증하지 않는다. 실제 자격증명이 별도로 확인되는 경우에만 소유자가 해당 서비스에서 폐기·교체 필요성을 검토해야 한다. Sheets ID 자체의 노출과 별도로 해당 문서의 실제 공유·접근 권한은 소유자가 확인할 수 있다.
